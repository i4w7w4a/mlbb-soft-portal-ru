# Operating Rules for Russian Site Administration

Эти правила нужны не для красоты. Они держат процесс в руках.

## 1. Working Root

Работать только в:

```text
C:\Users\iwwa\Documents\2_MLBB\site-ru
```

Папка:

```text
C:\Users\iwwa\Documents\2_MLBB\site
```

является английским эталоном. Ее не редактировать, не форматировать и не коммитить без отдельного прямого запроса.

## 2. Server Discipline

- Русская версия работает на `http://127.0.0.1:3001`.
- Английский сервер на `3000` держать выключенным во время русской работы.
- Перед визуальной проверкой убедиться, что открыт правильный порт.
- Если порт занят, сначала определить процесс, потом останавливать только нужный процесс.

## 3. Task Discipline

- Перед началом партии работ отметить задачу как `doing` в `tasks.md`.
- После проверки отметить задачу как `done`.
- Если задача заблокирована, поставить `blocked` и записать причину.
- Не держать скрытые задачи в голове. Если работа появилась, она должна появиться в `tasks.md`.
- Каждая крупная партия должна иметь проверку и, если прошла, отдельный коммит.

## 4. Decision Discipline

- Все решения, которые влияют на структуру, SEO, слаги, репозиторий или стиль, записывать в `decisions.md`.
- Не возвращаться к решенному вопросу без новой причины.
- Открытые вопросы не маскировать под решения.

## 5. Translation Discipline

- Использовать `glossary.md` как источник терминов.
- Не переводить `SOFT`, `MLBB`, `Mobile Legends: Bang Bang`, `EXP`, package names, URLs, slugs and code identifiers.
- Не переводить `slug`, `id`, `heroSlug`, taxonomy slugs без отдельного решения.
- Переводить пользовательский текст полностью:
  - navigation;
  - CTA;
  - labels;
  - filters;
  - placeholders;
  - loading states;
  - empty states;
  - errors;
  - admin actions;
  - SEO metadata;
  - markdown content.

## 6. Code Discipline

- Не делать масштабный рефакторинг ради эстетики.
- Использовать существующие паттерны проекта.
- Сохранять структуру английской версии там, где это помогает будущему переносу кода.
- Если строк много и они повторяются, можно создать словарь. Если русская версия отдельная и строка единичная, можно заменить прямо.
- Не добавлять новую библиотеку локализации без явной выгоды.

## 7. Validation Discipline

Минимальные проверки после контентного batch:

```bash
npm run content:check
```

Минимальные проверки после UI/code batch:

```bash
npm run typecheck
npm run lint
```

Финальные проверки:

```bash
npm run typecheck
npm run lint
npm test
npm run content:check
npm run metadata:check
npm run build
```

Если проверка упала, сначала понять причину, потом править. Не чинить вслепую.

## 8. Git Discipline

- Перед изменениями смотреть `git status --short --branch`.
- Коммитить только осмысленные batch-и.
- Не коммитить `node_modules`, `.next`, временные логи.
- После стабильного коммита делать push.
- Не менять remote без проверки `git remote -v`.

## 9. English Audit Discipline

Английский текст после перевода делится на два класса:

- allowed exception;
- defect.

Разрешенные исключения описаны в `qa-checklist.md`.

Если английская строка видна пользователю и не входит в исключения, это дефект.

## 10. Administration Standard

Безупречная администрация означает простую вещь:

- задача записана;
- решение записано;
- изменение ограничено;
- проверка выполнена;
- риск назван;
- следующий шаг ясен.

Все остальное - шум.
