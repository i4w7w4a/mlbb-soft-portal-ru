# Russian Version Master Plan

Дата старта: 2026-05-24

Цель: сделать полную русскую версию `SOFT Rift` в отдельном GitHub-репозитории, сохранив английскую версию как независимый исходник.

## Принцип работы

- Английский репозиторий остается эталоном структуры и будущих технических изменений.
- Русская версия получает отдельный репозиторий и отдельную рабочую папку.
- Структура файлов сохраняется максимально близкой к английской версии.
- Слаги героев и статей по умолчанию не переводятся, чтобы не ломать внутренние связи и контентный граф.
- Перевод не считается готовым, пока не пройдены кодовые проверки, контентные проверки и ручной просмотр ключевых маршрутов.

## Целевая архитектура русской версии

Русская версия должна быть отдельным сайтом, а не вторым языком внутри одного приложения.

Это дает простую форму:

- один репозиторий для английского сайта;
- один репозиторий для русского сайта;
- одинаковая структура кода;
- разные тексты, SEO и настройки сайта;
- минимум локализационной инфраструктуры.

Если позже понадобится переключатель языков, это будет отдельный этап. Сейчас он только усложнит путь.

## Основные фазы

### Phase 0. Baseline

Статус: completed on 2026-05-24.

Уже проверено в английской версии:

- `npm run typecheck`
- `npm run lint`
- `npm test`
- `npm run content:check`
- `npm run build`
- dev server: `http://127.0.0.1:3000`

### Phase 1. Russian Repository

Создать отдельную рабочую копию и новый remote.

Критерий готовности:

- английский репозиторий не потерян;
- русская копия открывается отдельно;
- `origin` у русской копии указывает на новый репозиторий;
- базовые проверки проходят до перевода.

### Phase 2. Translation Rules

Зафиксировать стиль, термины и непереводимые слова.

Критерий готовности:

- есть глоссарий;
- понятно, что делать с `SOFT`, `MLBB`, ролями, линиями и названиями героев;
- выбран тон сайта: редакционный, плотный, без машинной рыхлости.

### Phase 3. Content Translation

Перевести JSON-контент:

- `content/site/settings.json`
- `content/site/soft.json`
- `content/taxonomy/categories.json`
- `content/taxonomy/tags.json`
- `content/news/latest-index.json`
- `content/heroes/*/hero.json`
- `content/heroes/*/news/*.json`

Критерий готовности:

- контентный граф не сломан;
- все обязательные поля заполнены;
- markdown внутри статей переведен;
- SEO-поля переведены;
- `npm run content:check` проходит.

### Phase 4. UI Translation

Перевести строки интерфейса в `src`.

Критерий готовности:

- публичные страницы не показывают английские UI-строки;
- админка переведена достаточно, чтобы ей можно было пользоваться;
- состояния загрузки, пустые состояния, ошибки, фильтры и placeholder-ы переведены;
- скан по английским строкам показывает только разрешенные исключения.

### Phase 5. SEO and Metadata

Перевести метаданные и русифицировать технические настройки.

Критерий готовности:

- `lang="ru"` в root layout;
- OpenGraph locale: `ru_RU`;
- alt-тексты и image metadata на русском;
- title/description/keywords на русском;
- `npm run metadata:check` проходит.

### Phase 6. Visual and Functional QA

Проверить сайт как пользователь, не как компилятор.

Критерий готовности:

- `/`
- `/heroes`
- `/heroes/[slug]`
- `/news`
- `/news/[slug]`
- `/soft`
- `/search`
- `/admin`

Каждый маршрут открыт, визуально проверен и не содержит явного английского текста вне разрешенного списка.

### Phase 7. Final Release

Завершить репозиторий русской версии.

Критерий готовности:

- чистый `git status`;
- финальный коммит;
- remote GitHub создан;
- push выполнен;
- README русской версии обновлен;
- английский репозиторий сохранен.

## Главные риски

- Машинный перевод может разрушить редакционный тон.
- Английские строки могут остаться в UI, SEO или alt-текстах.
- Случайный перевод slug/id может сломать связи между героями, новостями и индексами.
- Русский текст длиннее английского и может ломать карточки, кнопки, фильтры.
- Две версии сайта потребуют дисциплины при будущих изменениях кода.

## Правило движения

Не делать следующий слой, пока предыдущий не проверен.

Слабое место такого проекта не в сложности кода. Слабое место в желании перевести все одним рывком и потом ловить сотню мелких трещин.
